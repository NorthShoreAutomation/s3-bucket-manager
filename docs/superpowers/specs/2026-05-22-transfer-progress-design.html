Summary

Add a progress bar, transfer-rate readout, and percentage-complete line to the local-file upload (p key) and object download (g key) flows in the TUI browse view. Reuse the rendering and ticker pattern already in place for URL→S3 uploads (internal/tui/urlupload.go), and consolidate the supporting helpers into a small shared package so all three transfer paths share one implementation.

Current state

  • URL→S3 upload (internal/tui/urlupload.go): already has a full progress UI — bubbles/progress bar, 250 ms ticker, atomic snapshot, plus formatRate / formatSize / formatDuration helpers and an ETA. Fed by an httpcopy.Progress callback.
  • Local file upload (internal/tui/buckets.go:1685): single-shot UploadObject with a static "Uploading X…" placeholder and a spinner. No byte-level feedback.
  • Object download (internal/tui/buckets.go:1820): DownloadObject → io.Copy, static "Downloading X…" placeholder and spinner. Total size is not currently surfaced.

Goals & non-goals

Goals. Bring upload and download to UX parity with URL upload: a visible bar, percentage complete, current rate, ETA when total is known. Single shared rendering path. Esc cancels an in-flight transfer cleanly.

Non-goals. Switching upload to multipart (UploadStream). Folder-level aggregate progress. Anything outside the browse view's p and g keypaths.

Architecture

Three components:

  1. A new shared package internal/progress holding the counting reader, the atomic snapshot type, and the formatting helpers.
  2. Extensions to bucketsModel in internal/tui/buckets.go to hold transfer state (bar, snapshot, rate, label, cancel func) and to handle a 250 ms tick message.
  3. Minimal changes to internal/aws/s3.go: DownloadObject's signature grows to also return the object's size.

Shared progress package

New package internal/progress:

package progress

type Snapshot struct {
    Done  int64
    Total int64 // -1 when unknown
}

// Reader wraps an io.Reader and reports the running byte count after each Read.
type Reader struct { /* … */ }
func NewReader(r io.Reader, onProgress func(done int64)) *Reader

// Helpers (moved from internal/tui/urlupload.go)
func FormatRate(bps float64) string
func FormatSize(n int64) string
func FormatDuration(d time.Duration) string
func ParseRateBytesPerSec(s string) float64

The existing countingReader in internal/httpcopy/copy.go is replaced by progress.Reader (no behavior change). urlupload.go is updated to import the formatters from the new package; its local copies are deleted.

Upload flow

When the user selects a file via the file picker:

  1. Set m.transferLabel = "Uploading " + filename.
  2. os.Stat the selected path to capture total bytes; store on the model as transferTotal.
  3. os.Open the file, then wrap in progress.NewReader whose callback stores a fresh *progress.Snapshot into an atomic.Pointer[progress.Snapshot] on the model.
  4. Call m.client.UploadObject(ctx, bucket, key, region, wrappedReader) from the goroutine.
  5. Return uploadDoneMsg on success, errMsg on failure (cancel returns errMsg with context.Canceled; see Cancel).

The 250 ms ticker reads the snapshot, recomputes transferRate (delta-bytes ÷ delta-time), and calls m.transferBar.SetPercent(done/total).

Download flow

DownloadObject currently returns (io.ReadCloser, error) and discards the GetObject response's Content-Length. It has a single caller (buckets.go), so widen the signature:

func (c *Client) DownloadObject(
    ctx context.Context, bucket, key, region string,
) (io.ReadCloser, int64, error)

The new int64 is the object size from output.ContentLength (or -1 when missing). The caller sets m.transferLabel = "Downloading " + item.Name, then wraps body in progress.NewReader before io.Copy to the destination file. Snapshot updates and ticker behavior mirror the upload flow.

Rendering

While m.transferSnap != nil, the browse view's existing one-line deleteProgress slot is replaced by two lines plus the label:

  Uploading photo.jpg
  ████████████░░░░░░░░░░░░░░░░░░
  12.4 MB / 50.0 MB (25%) — 8.3 MB/s — ETA 4s

Unknown-total fallback (defensive only; shouldn't occur for these flows): 12.4 MB — 8.3 MB/s.

The rest of the browse list remains visible above; the help row remains at the bottom but is replaced with [esc] cancel while a transfer is active.

Cancel behavior

The transfer goroutine is launched with a context.WithCancel whose cancel func is stored on the model as transferCancel. Pressing esc during a transfer:

  1. Calls m.transferCancel().
  2. The in-flight PutObject / GetObject unwinds with context.Canceled.
  3. The goroutine returns errMsg{err: ctx.Err()}.
  4. The update function detects errors.Is(err, context.Canceled) and shows "Cancelled" instead of an error.

ctrl+c retains its existing global meaning (quit the app).

Testing

  • internal/progress unit tests. Verify Reader reports byte count correctly across multiple reads; verify nil callback is safe; verify FormatRate/FormatSize/FormatDuration edge cases (0, negative, sub-KB, multi-GB). Port any existing relevant tests from urlupload_test.go if present.
  • internal/httpcopy regression. Existing tests must still pass after swapping countingReader for progress.Reader.
  • No new TUI integration test. The upload/download keypaths already work; this change is additive rendering and a widened return signature.

Out of scope

  • Switching local upload to multipart via UploadStream — track as a follow-up GitHub issue.
  • Folder-level aggregate progress — no folder upload/download flow exists today.
  • Changes to the URL-upload modal — that flow already has full progress and is only edited to import the moved helpers.
